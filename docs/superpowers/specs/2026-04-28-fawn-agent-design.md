## 1. 产品定位

为 0-6 个月新生儿家庭提供一个私有化、自部署的智能育儿 Agent。面向自家家庭成员使用，不是公共平台。

**核心能力：**
- 育儿知识指导（生长发育 + RAG 知识库，不做医疗诊断）
- 宝宝相册管理（AI 分类归档）
- 多角色对话（识别家庭成员身份）
- 综合记忆系统（短期 + 长期 + 全量存档）
- 数据收集与反馈（生长、喂养、睡眠、健康）

**交互形态：** Web 应用，Mobile-First 设计（主要在手机浏览器中使用）

**部署方式：** Docker Compose 容器化，先本地（NAS）部署，后续可迁移至云服务器

**非目标：**
- 不是公共平台或 SaaS 产品（仅自家使用）
- 不做原生移动应用（Mobile-First Web 设计）
- 不做多家庭/多租户支持（仅单个家庭）

---

## 2. 项目约束

- **团队规模：** 个人项目，AI 辅助编码，无其他开发者
- **时间线：** 无硬性 deadline，质量优先于速度
- **价值观：** 只接受"更优"的简化方案，不为省时间/资源而降低系统完整性
- **交付方式：** 所有模块同时交付，不做分阶段 MVP

---

## 3. 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| Agent 编排 | LangGraph | 图状态机，支持 deterministic + LLM 混合编排 |
| 后端框架 | FastAPI | Python 生态，与 LangGraph 无缝配合 |
| 前端框架 | Next.js (React) | AI 应用生态成熟，流式对话支持好 |
| 主力大模型 | Claude / GPT | 核心推理与对话能力，通过 LLM Provider 抽象层支持切换 |
| 主数据库 | PostgreSQL + pgvector | 结构化存储 + RAG 向量检索 |
| 缓存 | Redis | 会话状态、JWT 缓存 |
| 对象存储 | MinIO | 照片和知识库原文件存储，S3 兼容 |
| Embedding | text-embedding-3-small 或 bge-m3 | 知识库向量化 |
| LLM 抽象层 | 自建 Provider 接口 | 统一封装 Claude/GPT，支持按模块配置不同模型，一处切换 |

## 4. 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    Next.js 前端                       │
│       （Mobile-First 设计，手机浏览器为主）             │
│  对话界面 │ 数据看板 │ 相册浏览 │ 我的                 │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP / WebSocket
┌──────────────────────▼──────────────────────────────┐
│                  FastAPI 路由层                       │
│         认证中间件（JWT）→ 角色识别 → 路由分发         │
└──────────────────────┬──────────────────────────────┘
                       │
        ┌──────────────▼──────────────┐
        │     LangGraph Agent 核心     │
        │                             │
        │  1. 接收用户消息 + 角色信息    │
        │  2. 红旗规则引擎拦截检查       │
        │  3. 意图识别与路由            │
        │  4. 调用对应模块（作为 Tool）  │
        │  5. 汇总多方信息生成回答       │
        └──┬───┬───┬───┬───┬──────────┘
           │   │   │   │   │
     ┌─────┴┐ ┌┴───┴┐ ┌┴──┴┐────────┐
     │Advisor│ │Album│ │Memory      │
     │       │ │     │ │            │
     │ RAG   │ │ 上传 │ │ 短期记忆   │
     │ 知识库 │ │ 分类 │ │ 长期记忆   │
     │       │ │ 存储 │ │ 全量存档   │
     └───────┘ └─────┘ └────────────┘
     ┌───────┐ ┌──────────┐
     │Tracker│ │Auth      │
     │       │ │          │
     │ 生长   │ │ 账号管理  │
     │ 喂养   │ │ 角色权限  │
     │ 睡眠   │ │ JWT 签发  │
     │ 健康   │ │          │
     └───┬───┘ └──────────┘
         │
    ┌────▼─────────────────────────┐
    │         数据层                │
    │  PostgreSQL │ Redis │ MinIO  │
    └──────────────────────────────┘
```

### 核心数据流（对话示例）

1. 妈妈在前端发送："宝宝今天体重 4.2kg，是不是偏轻了？"
2. FastAPI 通过 JWT 识别角色：妈妈
3. LangGraph Agent 接收消息，意图识别为"数据记录 + 育儿咨询"
4. Agent 并行调用：
   - **Tracker** → 记录体重 4.2kg
   - **Memory** → 加载宝宝档案（出生日期、历史体重数据）+ 妈妈画像
   - **Advisor** → 查询 RAG 知识库（WHO 生长标准）
5. Agent 汇总所有信息，生成综合回答

## 5. 数据层设计

### 5.1 PostgreSQL（主存储）

所有结构化数据的唯一事实来源：

| 数据域 | 存储内容 |
|--------|---------|
| 用户与权限 | 账号信息、家庭成员关系、角色、权限配置 |
| 用户画像 | 每个家庭成员的 profile_summary（大模型维护的自然语言描述） |
| 宝宝档案 | 姓名、性别、出生日期、出生体重/身高/头围、是否早产（孕周）、校正月龄 |
| 生长数据 | 身高、体重、头围、测量日期、WHO 百分位计算结果（依赖性别+出生日期+测量日期） |
| 喂养数据 | 时间、方式（母乳/配方/辅食）、量 |
| 睡眠数据 | 入睡/醒来时间、睡眠时长、夜醒次数 |
| 健康数据 | 疫苗接种记录、生病记录、就医记录 |
| 对话历史 | 全量对话原文（永久保存，支持检索） |
| 对话摘要 | 每次对话的摘要和关键信息（长期记忆） |
| 知识库索引 | RAG 文档切片（chunks）+ 向量索引（pgvector） |

### 5.2 Redis（缓存）

| 用途 | 说明 |
|------|------|
| 会话状态 | 当前对话的上下文窗口，Agent 处理中的中间状态 |
| JWT Token 缓存 | 登录态验证 |
| 宝宝概要缓存 | 宝宝基本信息缓存，加速每次对话加载 |

Redis 中的数据丢失可从 PostgreSQL 重建。

### 5.3 MinIO（对象存储）

| 用途 | 说明 |
|------|------|
| 宝宝照片 | 原图存储，元数据（AI 标签、时间、描述）存 PostgreSQL |
| 知识库原文件 | 育儿书籍 PDF 等原始文件 |

照片存储路径：`/{baby_id}/{year}/{month}/{filename}`

## 6. 功能模块详细设计

### 6.1 红旗规则引擎（独立安全层）

**定位：** Agent 核心的独立安全层，使用确定性规则判断，**不依赖 LLM**，避免幻觉风险。位于意图识别之前，优先级最高。

**核心设计：** 红旗命中不等于短路所有流程。拦截的是诊断类回答，不拦截数据记录等非诊断操作。

```
用户消息进入
    │
    ▼
┌───────────────────────────────┐
│   红旗规则引擎（确定性分类）     │
│                               │
│   关键词匹配 + 模式识别         │
│                               │
│   命中 → 标记 safety_flag      │
│   未命中 → 正常放行             │
└──────────┬────────────────────┘
           │
           ▼
┌───────────────────────────────┐
│   安全回复约束                  │
│                               │
│   safety_flag = true 时：      │
│   ① 禁止诊断、用药、治疗建议    │
│   ② 必须附加就医提醒            │
│   ③ 回复由固定安全模板约束       │
│                               │
│   但允许非诊断类操作继续执行：    │
│   ✅ 数据记录（Tracker 写入）   │
│   ✅ 健康事件归档               │
│   ✅ 症状时间线记录             │
└──────────┬────────────────────┘
           │
           ▼
      正常 Agent 流程（受约束）
```

**示例：** 用户说"宝宝发烧 38.5，帮我记一下"
- 红旗命中（发烧）→ 标记 safety_flag
- Tracker 正常记录健康事件：体温 38.5°C
- 回复："已记录体温 38.5°C。**这个体温建议尽快咨询医生/就医。**"
- 不做任何诊断或安抚

**触发条件（示例）：**
- 疾病症状：发热、咳嗽、腹泻、呕吐、皮疹、黄疸加重
- 异常体征：呼吸异常、拒食、嗜睡、抽搐、发绀
- 语义触发："生病"、"不舒服"、"不对劲"、"要不要去医院"等表述

**核心原则：宁严勿松。** 不确定是否涉及医疗问题时，一律走拦截路径。

### 6.2 Advisor（育儿知识指导）

**定位：** 专注于 0-6 个月婴儿的生长发育和育儿知识指导，**不做医疗诊断和治疗建议**。经过红旗规则引擎放行后才进入本模块。

两层信息源架构：

```
用户提问（已通过红旗规则引擎）
    │
    ├──→ ① RAG 知识库检索
    │     向量相似度搜索 → 返回相关段落 + 来源标注
    │
    └──→ ② 主力大模型自身知识
          结合 ① 的结果 + 宝宝档案 + 用户画像 + 对话历史
          生成最终综合回答
```

**能做的（育儿指导范畴）：**
- 生长发育知识（翻身、抬头等里程碑时间参考）
- 喂养指导（母乳/配方奶量参考、辅食引入时机）
- 睡眠指导（睡眠时长参考、作息规律建议）
- 日常护理知识（洗澡、脐带护理、抚触等）
- 生长数据解读（WHO 百分位含义、趋势分析）

**设计原则：**
- 来源透明：回答中标注信息来自哪里（"根据《育儿百科》……"）
- 免责意识：所有健康相关回答附带提示"以医生意见为准"

### 6.3 Album（相册系统）

```
用户上传照片
    │
    ▼
FastAPI 接收文件 → 存入 MinIO
    │
    ▼
调用大模型 Vision API 分析照片
    │
    ├── 场景识别（吃饭、睡觉、户外、洗澡……）
    ├── 候选里程碑检测（疑似翻身、疑似第一次笑等，需用户确认）
    └── 表情/状态识别（开心、哭闹、睡着……）
    │
    ▼
生成标签 + 结合上传时间 → 写入 PostgreSQL
（AI 标签保存置信度、可编辑状态、人工确认状态）
    │
    ▼
自动归档到对应分类（按时间线 / 按场景 / 按里程碑）
```

**三种分类维度：**
- 按时间：自动按天/周/月归类
- 按场景：AI 识别内容后打标签分类
- 按里程碑：AI 候选检测 + 用户确认后归档（单张照片不能可靠判断"第一次"）

### 6.4 Memory（记忆系统）

三层架构：

| 层级 | 内容 | 用途 | 存储 |
|------|------|------|------|
| 短期记忆 | 当前会话的对话上下文 | Agent 实时对话，维持当前会话连贯性 | Redis + PostgreSQL |
| 长期记忆 | 每次对话的摘要与关键信息 | 每次新对话自动加载，Agent "记得"之前聊过什么 | PostgreSQL |
| 全量对话存档 | 所有历史对话完整原文，永久保存 | 面向用户的检索功能，按日期/关键词搜索任意对话 | PostgreSQL |

**工作流程：**

```
用户发起对话
    │
    ▼
加载短期记忆（当前会话上下文）
  + 加载长期记忆（历史对话摘要 + 宝宝档案概要 + 用户画像）
    │
    ▼
Agent 对话过程中，消息实时写入短期记忆
    │
    ▼
对话结束后
    ├──→ 全量对话原文 → 存入对话存档（永久保存）
    ├──→ Agent 生成本次摘要 → 写入长期记忆
    └──→ Agent 判断是否更新用户画像 → 如有新认知则更新
```

**会话边界判定：**
- 用户主动开始新对话（点击"新对话"按钮）
- 或超过 30 分钟无活动，自动视为当前会话结束
- 会话结束后触发摘要生成和用户画像更新

**对话检索：**
- 前端"历史对话"页面，支持按日期浏览、按关键词搜索
- 实现方式：PostgreSQL LIKE 模糊匹配（家庭级数据量足够）
- 完整展示历史对话内容，包含文字、图片引用等

### 6.5 Tracker（数据收集与反馈）

四个数据域，通过对话式自然语言输入：

| 数据域 | 记录字段 | 反馈能力 |
|--------|---------|---------|
| 生长 | 身高、体重、头围、测量日期 | WHO 百分位对比、生长趋势曲线 |
| 喂养 | 时间、方式（母乳/配方/辅食）、量、备注 | 日累计量、喂养间隔分析 |
| 睡眠 | 入睡/醒来时间、夜醒次数、类型 | 日均睡眠时长、与月龄参考对比 |
| 健康 | 疫苗接种、生病记录、症状描述 | 疫苗日程提醒、健康时间线 |

**对比标准：** WHO 生长曲线等权威标准数据。

### 6.6 Auth（用户与角色管理）

**角色体系：**

| 角色 | 权限 |
|------|------|
| Admin | 管理所有账号、分配角色、系统配置、全部功能 |
| Parent（父母） | 全部功能：对话、记录、查看、上传照片 |
| Family（其他成员） | 可对话、可查看记录，上传照片需看配置 |

**实现方式：**
- JWT 认证，Token 中携带 user_id 和 role
- 认证中间件提取角色信息，Agent 自动知道"谁在问"
- Admin 通过 Web 管理界面管理家庭成员

### 6.7 用户画像系统

每个家庭成员维护一份自然语言描述的用户画像，由大模型自动维护。

**存储：** PostgreSQL 用户表中的 `profile_summary` (TEXT) 字段。

**画像内容示例：**

```
【妈妈 - 张XX】
- 母乳喂养中，奶量充足，偶尔焦虑奶量是否够
- 比较关注宝宝睡眠质量，曾多次咨询夜醒问题
- 倾向于自然育儿，对过度干预比较抵触
- 产后第 6 周，偶尔提到腰酸，情绪状态整体良好
```

**维护方式：**
- 每次对话结束后，Agent 判断是否产生了关于该用户的新认知
- 如有新认知则更新 profile_summary，否则不动
- 更新时标注来源对话 ID，保留可追溯性
- 每次对话开始时与宝宝档案一起注入 Agent 上下文

**隐私与纠错机制：**
- 用户可在"我的"页面查看自己的画像内容
- 用户可手动编辑或删除画像中的任意内容
- 画像仅记录与育儿相关的事实性信息，避免主观推断（如"焦虑"等情绪判断）
- 画像内容不对其他非 Admin 角色可见

## 7. LangGraph Agent 核心设计

### 7.1 状态图

```
用户消息进入
    │
    ▼
┌──────────────────┐
│  红旗规则引擎拦截  │  确定性规则，不依赖 LLM
│                  │
│  命中 → 直接返回   │  固定就医提醒模板
│  未命中 → 放行     │
└──────┬───────────┘
       │
       ▼
┌─────────────┐
│  意图识别    │  判断用户想做什么
└──────┬──────┘
       │
       ▼
┌─────────────────────────────────────┐
│           路由分发                    │
│                                     │
│  记录类 → Tracker                    │
│  咨询类 → Advisor（RAG 知识库）       │
│  照片类 → Album                      │
│  查询类 → Memory / Tracker           │
│  闲聊类 → 直接由主力大模型回答         │
│  混合类 → 并行调用多个模块            │
└──────┬──────────────────────────────┘
       │
       ▼
┌─────────────┐
│  汇总生成    │  整合各模块结果，生成自然语言回答
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  记忆更新    │  写入短期记忆，触发对话存档
└─────────────┘
```

### 7.2 模块注册

每个功能模块作为 LangGraph 的 Tool 注册，Agent 根据意图决定调用哪些 Tool。支持单次对话中调用多个模块（如"宝宝今天 4.5kg，是不是正常？"同时触发 Tracker 和 Advisor）。

### 7.3 多角色上下文注入

```
请求进入 → JWT 解码 → 提取 user_id + role
    │
    ▼
Agent 的 System Prompt 动态注入：
- 当前对话者角色和姓名
- 该用户的画像（profile_summary）
- 宝宝档案概要
- 历史对话摘要（长期记忆）
```

Agent 的回答语气和侧重点会根据角色和用户画像自动调整。

## 8. RAG 知识库

### 8.1 构建流程（离线）

```
书籍 PDF → 文档解析 → 切片（chunk）→ Embedding → 存入 PostgreSQL (pgvector)
```

- 切片策略：按段落切，保留章节标题作为元数据
- 增量式建设：开发过程中逐步收集公开权威育儿资料，随时可添加新内容并重新跑 Embedding

### 8.2 来源准入规则

| 允许入库 | 不允许入库 |
|---------|-----------|
| WHO/CDC/卫健委等官方指南 | 个人博客、论坛帖子 |
| 权威育儿书籍（专业作者出版物） | UGC 内容（无法验证准确性） |
| 医学期刊公开摘要 | 商业推广内容 |

每份入库资料需记录：来源名称、作者/机构、出版/发布日期、版本号。

### 8.3 查询流程（在线）

```
用户问题 → Embedding → 向量相似度检索 → Top-K 相关段落 → 注入 LLM Prompt
```

### 8.4 低置信度策略

- 检索结果相似度低于阈值时，明确告知用户"知识库中未找到相关信息，建议咨询医生或查阅专业资料"
- 健康/医疗相关问题不得仅依赖大模型自身常识回答，必须有知识库依据或明确标注"以下为大模型通用知识，仅供参考"
- 回答中标注信息来源（书名、章节），用户可自行验证

## 9. 前端界面规划

**设计原则：** Mobile-First，主要在手机浏览器中使用。

### 页面结构

```
┌─────────────────────────────────┐
│           顶部导航栏              │
│  Logo(Fawn)  │  当前用户/角色     │
└──────────────┬──────────────────┘
               │
         页面内容区域
               │
    ┌──────────▼──────────┐
    │      底部 Tab 导航    │
    │  对话 │ 数据 │ 相册 │ 我的 │
    └──────────────────────┘
```

### 四个主要页面

**对话页（核心）：**
- 类似微信聊天界面，支持文字输入和图片发送
- 消息气泡区分用户和 Agent
- Agent 回答中可嵌入数据卡片（生长曲线小图、统计摘要等）
- 顶部入口进入"历史对话"检索页（按日期浏览 + 关键词搜索）

**数据看板页：**
- 宝宝基本信息卡片（月龄、最新体重身高）
- 生长曲线图（体重/身高随时间变化 + WHO 百分位参考线）
- 近期喂养统计（日均奶量、喂养次数趋势）
- 近期睡眠统计（日均睡眠时长、夜醒次数趋势）
- 健康时间线（疫苗接种、生病记录）

**相册页：**
- 三种浏览模式切换：时间线 / 按场景分类 / 按里程碑
- 照片点击放大、查看 AI 标签
- 上传入口（拍照或从相册选择）

**我的页面：**
- 个人信息和角色展示
- 宝宝档案查看/编辑
- Admin 专属：家庭成员管理（添加/删除成员、分配角色）
- 系统设置

## 10. 部署架构

```yaml
# Docker Compose 服务编排
services:
  frontend:     # Next.js 前端
  backend:      # FastAPI + LangGraph
  postgres:     # PostgreSQL + pgvector
  redis:        # Redis 缓存
  minio:        # MinIO 对象存储
```

- 一条 `docker compose up` 全部启动
- 先部署在本地 NAS，后续可无缝迁移至云服务器
- 所有服务容器化，环境一致性有保障

**初始化与运维：**
- 数据库 migrations 脚本，可重复执行
- pgvector 扩展自动初始化
- MinIO bucket 自动创建
- 持久化 volume 配置（PostgreSQL 数据、MinIO 文件、Redis 持久化）
- 环境变量配置文件（`.env`）管理 LLM API Key、数据库密码等敏感信息
- 各服务健康检查（health check）配置
- 数据备份/恢复脚本

## 11. 项目结构

```
fawn/
├── agent/              # LangGraph Agent 核心（对话编排、意图路由）
├── modules/
│   ├── advisor/        # 育儿知识指导（LLM + RAG）
│   ├── album/          # 相册系统（上传、AI 分类、存储）
│   ├── memory/         # 记忆系统（短期 + 长期 + 全量存档）
│   ├── tracker/        # 数据收集与反馈（生长、喂养、睡眠、健康）
│   └── auth/           # 用户与角色管理
├── safety/             # 红旗规则引擎（独立确定性安全层）
├── llm/                # LLM Provider 抽象层（Claude/GPT 可切换）
├── api/                # FastAPI 路由层
├── knowledge/          # RAG 知识库（embedding、检索）
├── frontend/           # Next.js 前端（Mobile-First）
├── docker-compose.yml
└── README.md
```

模块化单体架构：一个可部署单元，内部按功能域划分清晰的模块边界。

## 12. 验收标准

- [ ] **核心对话场景：** 妈妈发送"宝宝今天体重4.2kg，是不是偏轻了？"，Agent 基于已有宝宝档案（性别、出生日期）和测量日期计算 WHO 百分位，同时完成：①记录体重数据到 Tracker ②加载宝宝历史数据和档案 ③结合 RAG 知识库给出基于 WHO 标准的回答
- [ ] **多角色数据共享：** 妈妈记录喂养数据后，奶奶登录并询问"宝宝今天吃了多少"，Agent 能基于奶奶的角色和妈妈记录的数据给出回答
- [ ] **照片上传 + AI 分类：** 上传照片后，Vision API 自动识别场景并打标签（含置信度），里程碑为候选检测需用户确认，照片可按时间线/场景/里程碑三种模式浏览
- [ ] **数据可视化看板：** 数据看板页展示生长曲线（含 WHO 百分位参考线）、喂养统计、睡眠统计
- [ ] **历史对话检索：** 所有对话永久保存，支持按日期浏览和关键词搜索
- [ ] **红旗规则引擎：** 涉及疾病/异常体征时，确定性规则拦截（不依赖 LLM），明确提醒就医
- [ ] **记忆系统工作：** 对话结束后自动生成摘要写入长期记忆，下次对话自动加载历史上下文
- [ ] **用户画像自动维护：** Agent 根据对话内容自动更新家庭成员画像，并根据角色调整回答语气
- [ ] **LLM 可切换：** 通过配置可在 Claude 和 GPT 之间切换，或为不同模块指定不同模型
- [ ] **一键部署：** `docker compose up` 即可启动全部服务
- [ ] **家人体验验证：** 家庭成员实际使用一周后评价"比直接用 ChatGPT 好用"
