## 1. 执行摘要

本文档为"宝宝专属 agent"定义 **安全（Safety）、隐私（Privacy）、合规（Compliance）** 的完整框架。核心立场：

| 原则 | 一句话 |
|---|---|
| **医疗定位** | 本产品是 *育儿记录与信息辅助工具*，**不是**诊断系统，不替代任何医疗专业人员 |
| **安全默认** | 高风险场景（红旗症状、异常生长、疫苗不良反应）默认升级至线下就医/急救，不做"安抚式"回答 |
| **隐私保守** | 儿童数据按最严格标准处理：最小收集、端到端加密、显式授权、可随时删除 |
| **规则优先** | 医疗安全判断 100% 由 deterministic rules 执行，LLM 不持有否决权 |
| **版权守法** | 不全文入库任何版权内容；引用遵循 fair-use 最小片段 + 来源链接 |

本文档输出的约束将直接写入 D1（schema 必须字段/加密列）、E1（安全 eval 用例集）、G1（发布门禁 checklist）。

## 2. 风险分级与默认原则

### 2.1 四级风险矩阵

| 级别 | 定义 | 典型场景 | 默认处理 |
|---|---|---|---|
| **P0 — 生命安全** | 可能延误急救或导致错误处置 | 红旗症状（高热惊厥、呼吸困难、嗜睡拒食）、严重过敏 | **立即展示急救指引 + 强制建议拨打 120/就近急诊**；不允许 LLM 自由发挥 |
| **P1 — 健康偏差** | 可能导致亚健康或错过窗口期 | 生长曲线持续偏离、疫苗逾期、发育里程碑显著落后 | **标记异常 + 建议预约儿科复查**；给出结构化参考值 |
| **P2 — 信息误导** | 可能传播不准确育儿信息 | 辅食添加、睡眠训练方法争议、民间偏方 | **标注来源等级 + 提示"咨询儿科医生"**；LLM 可参与但需标注置信度 |
| **P3 — 体验瑕疵** | 不影响安全但影响信任 | 记录格式错误、提醒时间不准、多成员同步延迟 | 常规 bug-fix 流程 |

### 2.2 默认原则（5 条硬规则）

1. **Fail-safe 优先**：任何不确定场景向更高风险级别对齐。
2. **Rule Engine 否决权**：safety_gate（A2 架构中的最终否决点）对所有输出有 veto 权，LLM 不可覆盖。
3. **不做排除性诊断**：永远不输出"不是 XX 疾病"这类排除性结论。
4. **显式分级标签**：每条健康相关回答必须携带 `risk_level` 和 `source_tier` 元数据。
5. **人类兜底**：P0/P1 场景的最终建议必须指向人类专业人员（医生/急救）。

## 3. 医疗定位边界

### 3.1 能做 / 不能做 / 必须升级

| 类别 | 具体范围 | 执行方式 |
|---|---|---|
| ✅ **能做** | 记录喂养量/次数/时间 | 数据入库，趋势可视化 |
| ✅ **能做** | 记录睡眠时长/模式 | 数据入库，与月龄参考范围对比 |
| ✅ **能做** | 记录身高/体重/头围，绘制 WHO 生长曲线 | Deterministic：WHO Z-score 计算 |
| ✅ **能做** | 疫苗日程提醒（基于中国免疫规划 / CDC 推荐） | Deterministic：规则引擎排程 |
| ✅ **能做** | 一般育儿知识问答（辅食顺序、洗澡温度等） | LLM + RAG（L3/L4），标注来源 |
| ✅ **能做** | 发育里程碑对照提示 | Deterministic：CDC 里程碑 checklist |
| ⚠️ **受限** | 症状描述 → 可能原因列举 | LLM 生成但 **必须经 safety_gate 审查**，附免责声明 |
| ⚠️ **受限** | 用药/剂量信息查询 | 仅展示权威来源原文片段 + 链接，**不做剂量计算/推荐** |
| 🚫 **不能做** | 出具诊断结论 | 硬编码拒绝 |
| 🚫 **不能做** | 推荐处方药 / 修改医嘱 | 硬编码拒绝 |
| 🚫 **不能做** | 替代急救指导（如窒息急救步骤的"个性化调整"） | 仅展示标准急救流程原文，不允许 LLM 改写 |
| 🔴 **必须升级** | 红旗症状触发 | Deterministic rule → 中断对话 → 展示急救/就医指引 |
| 🔴 **必须升级** | 生长 Z-score < -3 或 > +3 | Deterministic rule → 强提示就医 |
| 🔴 **必须升级** | 疫苗严重不良反应描述 | Deterministic rule → 就医指引 |

### 3.2 红旗症状硬编码列表（示例，非穷举）

以下症状触发 P0 强制升级，由规则引擎基于关键词 + 结构化症状字段匹配，**不经过 LLM 判断**：

```
# 0-12 月
- 体温 ≥ 38.0°C（< 3月龄）或 ≥ 39.0°C（3-12月龄）持续不退
- 呼吸急促 / 呼吸困难 / 胸骨凹陷
- 嗜睡 / 难以唤醒
- 拒绝进食 > 8h（< 6月龄）
- 持续呕吐 > 6h
- 皮肤发绀 / 苍白
- 囟门凸起或明显凹陷
- 抽搐 / 惊厥
- 血便

# 所有月龄
- 误服异物 / 中毒
- 跌落后意识改变
- 严重烫伤 / 烧伤
- 过敏性休克症状（面部肿胀 + 呼吸困难）
```

**实现约束**：此列表存储于 L1 层（硬编码医学规则），版本受控，变更需医学顾问 review + 双人审批。

## 4. Deterministic Rules vs LLM 分工矩阵

| 功能域 | Deterministic Rules | LLM 角色 | 谁拥有最终决定权 |
|---|---|---|---|
| 红旗症状识别 | ✅ 关键词匹配 + 阈值判断 | 辅助意图理解（将自然语言映射为结构化症状字段） | **Rule Engine** |
| 生长曲线评估 | ✅ WHO Z-score 计算 + 阈值告警 | 生成家长可读解释文本 | **Rule Engine** |
| 疫苗排程 | ✅ 免疫规划日程计算 | 生成提醒文案 | **Rule Engine** |
| 喂养/睡眠记录 | ✅ 数据校验（合理范围检查） | 自然语言解析 → 结构化数据 | **Rule Engine**（校验）/ LLM（解析） |
| 发育里程碑 | ✅ 月龄匹配 checklist | 生成鼓励性/建议性文案 | **Rule Engine** |
| 一般育儿问答 | ❌（但 safety_gate 做输出过滤） | ✅ RAG + 生成 | **safety_gate** 有否决权 |
| 家庭协作功能 | ✅ 权限校验（RBAC） | 辅助生成摘要/通知文案 | **RBAC 引擎** |
| 免责声明插入 | ✅ 基于 risk_level 自动附加 | ❌ 不参与 | **Rule Engine** |

**关键 trade-off 与推荐**：

- **为什么不让 LLM 直接判断红旗症状？** LLM 存在幻觉风险，可能在高置信度下给出错误的"安全"判断。对于 P0 场景，假阴性的后果远大于假阳性的体验损失。因此强制使用 deterministic rules，接受一定的假阳性率。
- **为什么 LLM 仍参与症状意图理解？** 家长描述症状的方式高度多样化（"宝宝一直哭不停怎么办"可能隐含多种症状）。LLM 的作用是将自然语言映射为结构化症状字段（如 `{crying_duration: ">2h", feeding_refusal: true}`），然后由 rule engine 判断。
- **推荐方案**：LLM 做"翻译"，Rule Engine 做"判断"，safety_gate 做"否决"。三层串联，不可跳过。

## 5. 儿童隐私与家庭多成员权限模型

### 5.1 适用法规与对标标准

| 法规/标准 | 适用范围 | 对本产品的关键要求 |
|---|---|---|
| **中国《个人信息保护法》(PIPL)** | 中国用户 | 不满 14 周岁的未成年人信息属于"敏感个人信息"，必须取得父母/监护人单独同意 |
| **中国《未成年人保护法》** | 中国用户 | 网络产品不得收集非必要未成年人信息 |
| **COPPA (美国)** | 若服务美国用户 | 13 岁以下儿童数据需 verifiable parental consent |
| **GDPR Art.8 (欧盟)** | 若服务欧盟用户 | 16 岁以下（成员国可降至 13 岁）需父母同意 |
| **推荐对标** | 全球 | 按 PIPL（最严格之一）作为默认基线 |

### 5.2 数据分类与敏感度

| 数据类型 | 示例 | 敏感级别 | 存储要求 |
|---|---|---|---|
| **儿童身份信息** | 姓名、出生日期、性别 | 🔴 高 | 加密存储，最小收集 |
| **健康记录** | 身高/体重/头围、喂养/睡眠记录、症状描述 | 🔴 高 | 加密存储，访问审计 |
| **医疗相关** | 疫苗接种记录、过敏史、用药记录 | 🔴 高 | 加密存储，变更不可篡改 |
| **家庭关系** | 父母/祖父母/保姆角色绑定 | 🟡 中 | 加密存储 |
| **设备/行为** | 登录时间、功能使用频率 | 🟢 低 | 可脱敏后用于产品分析 |
| **对话历史** | 与 agent 的问答记录 | 🟡 中-高（可能含健康信息） | 加密存储，定期清理 |

### 5.3 家庭多成员权限模型（推荐方案）

```
┌─────────────────────────────────────────────┐
│              Family Unit (家庭)              │
│                                             │
│  ┌─────────┐  ┌─────────┐  ┌──────────┐   │
│  │ Primary  │  │ Co-     │  │ Viewer   │   │
│  │ Guardian │  │ Guardian│  │ (只读)   │   │
│  │ (主监护人)│  │(共同监护)│  │ 祖父母/  │   │
│  │          │  │         │  │ 保姆     │   │
│  └────┬─────┘  └────┬────┘  └────┬─────┘   │
│       │              │            │          │
│  全部权限        大部分权限    只读+限定     │
│                                             │
│  ┌──────────────────────────────────────┐   │
│  │        Baby Profile (宝宝档案)       │   │
│  │  - 基本信息  - 健康记录  - 疫苗      │   │
│  │  - 喂养/睡眠  - 对话历史             │   │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

| 权限 | Primary Guardian | Co-Guardian | Viewer |
|---|---|---|---|
| 查看所有记录 | ✅ | ✅ | ✅（仅限被授权的数据范围） |
| 添加/编辑记录 | ✅ | ✅ | ❌ |
| 与 agent 问答 | ✅ | ✅ | ✅（只读上下文，不可触发写操作） |
| 管理家庭成员 | ✅ | ❌ | ❌ |
| 删除宝宝数据 | ✅ | ❌（需 Primary 确认） | ❌ |
| 导出数据 | ✅ | ✅（需 Primary 授权） | ❌ |
| 修改隐私设置 | ✅ | ❌ | ❌ |
| 查看审计日志 | ✅ | ❌ | ❌ |

**推荐实现约束**：
- 每个 Family Unit 最多 1 个 Primary Guardian，由注册时指定。
- Primary Guardian 转让需身份验证 + 72 小时冷静期。
- Viewer 角色不能看到完整对话历史（可能含敏感症状讨论），仅看到结构化记录摘要。
- 所有角色的操作均记录审计日志（who/what/when）。

### 5.4 数据最小化原则

| 原则 | 实施方式 |
|---|---|
| **收集最小化** | 仅收集功能必需数据；宝宝姓名可用昵称替代；不要求上传照片（可选） |
| **存储最小化** | 对话历史默认保留 90 天后自动摘要化（保留结构化数据，删除原始对话） |
| **使用最小化** | LLM 推理时仅传入当前对话所需上下文，不传入全量历史 |
| **共享最小化** | 不与任何第三方共享儿童数据；匿名统计数据需 opt-in |

## 6. 加密、密钥、审计、数据保留与删除策略

### 6.1 加密方案（推荐默认）

| 层级 | 方案 | 说明 |
|---|---|---|
| **传输加密** | TLS 1.3 | 所有 API 通信，HSTS 强制 |
| **静态加密 — 数据库** | AES-256-GCM（列级加密） | 敏感字段（姓名、出生日期、健康记录）列级加密；非敏感字段表级加密 |
| **静态加密 — 文件存储** | AES-256 | 导出文件、备份文件 |
| **静态加密 — 日志** | AES-256 | 审计日志加密存储，防篡改 |
| **密钥管理** | 自托管 KMS 或云 KMS（如 AWS KMS / Azure Key Vault） | 密钥轮换周期 ≤ 90 天；主密钥与数据密钥分离 |

**Trade-off 说明**：
- **列级加密 vs 全库加密**：列级加密性能开销更大（约 5-15%），但允许在数据库层面实现细粒度访问控制，对儿童健康数据场景更合适。推荐对 🔴 高敏感字段使用列级加密，🟡 中敏感字段使用表级加密。
- **端到端加密 vs 服务端加密**：端到端加密（客户端加密）会导致服务端无法执行 rule engine 检查和 LLM 推理。推荐方案：服务端加密 + 严格的服务端访问控制 + 审计日志。

### 6.2 审计日志要求

| 审计事件 | 记录内容 | 保留期限 |
|---|---|---|
| 用户登录/登出 | user_id, timestamp, IP, device | 1 年 |
| 数据读取 | user_id, data_type, baby_id, timestamp | 1 年 |
| 数据写入/修改 | user_id, data_type, baby_id, old_value_hash, new_value_hash, timestamp | 3 年 |
| 数据删除 | user_id, data_type, baby_id, timestamp, deletion_type | 3 年 |
| 权限变更 | operator_id, target_user_id, old_role, new_role, timestamp | 3 年 |
| 红旗症状触发 | session_id, symptom_matched, rule_id, response_shown, timestamp | 3 年 |
| safety_gate 否决 | session_id, original_output_hash, rejection_reason, timestamp | 3 年 |
| 数据导出 | user_id, export_scope, timestamp | 3 年 |

**推荐**：审计日志使用 append-only 存储（如 AWS CloudTrail、自建 immutable log），防止事后篡改。

### 6.3 数据保留与删除策略

| 数据类型 | 默认保留期 | 删除方式 | 用户可自主操作 |
|---|---|---|---|
| 结构化健康记录 | 无限（直到用户主动删除） | 硬删除 + 备份清理 | ✅ Primary Guardian 可随时删除 |
| 对话历史 | 90 天 | 自动摘要化（提取结构化数据后删除原文） | ✅ 可随时手动删除 |
| 审计日志 | 3 年 | 到期自动清理 | ❌（合规要求，不可用户删除） |
| 账户注销 | 30 天冷静期后永久删除所有数据 | 硬删除 + 所有备份在 90 天内清理 | ✅ Primary Guardian 发起 |
| 匿名统计数据 | 无限 | N/A | ❌（已脱敏，无法关联个人） |

**"被遗忘权"实施**：
- 用户请求删除时，除审计日志外的所有个人数据在 30 天内完成删除。
- 已进入备份的数据在下一个备份轮换周期（≤ 90 天）内清理。
- 删除确认通知发送给 Primary Guardian。

## 7. 版权/许可边界与内容使用策略

### 7.1 来源分级使用策略（衔接 B2 结论）

| 来源层级（B2） | 使用方式 | 版权策略 |
|---|---|---|
| **可直接用于 deterministic rules**：WHO 生长标准、CDC 免疫程序、中国卫健委规范等 | 数值/阈值/日程硬编码入规则引擎 | 公共数据/政府开放数据，可自由使用；标注来源 |
| **可 structured reference + RAG 引用**：WHO 立场文件、NHS、NICE、MedlinePlus | 摘要/片段引用 + 来源链接 | 遵循各来源 terms of use；不全文入库；引用标注 |
| **仅 metadata registry**：AAP HealthyChildren、UNICEF parenting | 仅存储标题/URL/摘要 metadata | 不入库正文；引导用户访问原站 |
| **用户生成内容（UGC）** | 不入库、不引用 | 无法验证准确性和版权 |
| **许可不确定来源** | 默认不使用，标记"需人工复核" | 保守处理：宁可不用 |

### 7.2 内容使用红线

1. **不全文复制**任何版权内容到知识库。
2. **不生成**暗示本产品拥有原创医学内容的回答。
3. **不去除**来源归属信息。
4. **不缓存**版权内容的完整页面。
5. **引用片段**控制在 fair-use 合理范围内（一般不超过原文 10%，且需变换性使用）。

### 7.3 内容更新与审核流程

```
来源更新 → 医学顾问审核 → 双人批准 → 版本化入库 → 旧版本归档（不删除，保留审计）
```

- L1/L2 层内容变更需医学专业人员 review。
- L3/L4 层内容变更需产品 + 医学双重 review。
- 变更记录写入审计日志。

## 8. 免责声明模板

### 8.1 常规健康建议免责声明

```markdown
📌 **温馨提示**
以上信息仅供参考，不构成医疗诊断或治疗建议。
每个宝宝的情况不同，具体健康问题请咨询您的儿科医生。
信息来源：{source_name}（{source_url}）
```

**触发条件**：所有 risk_level ≥ P2 的健康相关回答自动附加。
**实现方式**：Deterministic rule，基于 `response.risk_level` 和 `response.category` 自动插入。

### 8.2 红旗症状紧急声明

```markdown
🚨 **请立即就医**
根据您描述的症状（{matched_symptoms}），建议您：
1. **立即拨打 120 急救电话**或前往最近的儿童急诊
2. 在等待救援时，保持宝宝呼吸道通畅
3. 不要自行给药

本应用无法替代专业医疗评估。
当前识别到的异常指标：{alert_details}
```

**触发条件**：规则引擎匹配到红旗症状关键词/阈值。
**实现方式**：Deterministic rule 直接输出，**不经过 LLM**，不允许 LLM 修改措辞。

### 8.3 数据与隐私告知声明

```markdown
🔒 **数据与隐私说明**
```

## 9. 事故响应与发布门禁建议

### 9.1 安全事故分级与响应

| 事故级别 | 定义 | 响应时间 | 处置方式 |
|---|---|---|---|
| **S0 — 数据泄露** | 儿童个人数据/健康数据泄露 | ≤ 1 小时 | 立即下线受影响服务 → 通知受影响用户 → 72 小时内报告监管机构（PIPL 要求） |
| **S1 — 安全逻辑失效** | safety_gate 被绕过、红旗症状未触发 | ≤ 2 小时 | 回滚到上一安全版本 → 根因分析 → 增加 E1 测试用例 |
| **S2 — 医疗信息错误** | LLM 输出了明显错误的医疗信息 | ≤ 4 小时 | 该类别问答临时降级为"请咨询医生" → 修复 + review |
| **S3 — 功能异常** | 记录丢失、同步失败等 | ≤ 24 小时 | 常规 incident 流程 |

### 9.2 发布门禁 Checklist（→ E1/G1）

每次版本发布前必须通过以下门禁：

```
[ ] 1. safety_gate 单元测试全部通过（覆盖所有红旗症状场景）
[ ] 2. 免责声明插入测试通过（所有模板在对应场景正确展示）
[ ] 3. RBAC 权限测试通过（越权访问测试 0 通过）
[ ] 4. 加密字段验证（敏感字段确认加密存储）

[ ] 6. 数据删除流程验证（删除请求在 SLA 内完成）
[ ] 7. 审计日志完整性验证
[ ] 8. 版权合规审查（新增知识来源的许可确认）
[ ] 9. 隐私政策文本与实际行为一致性检查
[ ] 10. 医学内容变更的专业人员 sign-off
```

## 11. 推荐默认方案与不推荐做法

### 11.1 推荐默认方案

| 领域 | 推荐方案 | 理由 |
|---|---|---|
| **医疗安全** | 三层串联：LLM 翻译 → Rule Engine 判断 → safety_gate 否决 | 最大化安全性，每层独立可测试 |
| **隐私基线** | 以中国 PIPL 为基线，兼顾 COPPA/GDPR | PIPL 对儿童数据要求最严格之一 |
| **加密** | 敏感字段列级 AES-256-GCM + 传输 TLS 1.3 | 平衡安全性和性能 |
| **权限模型** | Primary Guardian / Co-Guardian / Viewer 三级 | 覆盖典型家庭结构，简洁可理解 |
| **对话保留** | 90 天自动摘要化 | 平衡功能需求和隐私风险 |
| **免责声明** | 基于 risk_level 自动插入，不可关闭 | 避免遗漏 |
| **红旗症状** | 硬编码规则 + 强制就医指引，不经 LLM | 零容忍假阴性 |
| **版权处理** | 不全文入库 + 引用标注 + 链接原站 | 保守合法 |
| **部署** | 自托管优先 | 最大化数据控制权 |

### 11.2 明确不推荐的做法

| 不推荐做法 | 风险 | 替代方案 |
|---|---|---|
| ❌ 让 LLM 直接判断症状严重程度 | 幻觉导致假阴性，延误就医 | Rule Engine 判断 |
| ❌ 将儿童数据存储在第三方 SaaS | 数据主权不可控 | 自托管或数据主权明确的云服务 |
| ❌ 全文入库版权内容 | 版权侵权风险 | 片段引用 + 链接 |
| ❌ 默认保留所有对话历史 | 隐私风险累积 | 90 天自动清理 |
| ❌ 用"概率"表述安全风险（"可能没事"） | 误导家长低估风险 | 明确建议就医或不建议 |
| ❌ 允许 Viewer 角色看到完整对话历史 | 可能含敏感健康讨论 | 仅展示结构化记录摘要 |
| ❌ 跳过 safety_gate 的任何快捷路径 | 安全架构失效 | safety_gate 串联不可跳过 |
| ❌ 在 LLM 提示词中包含完整儿童数据 | 扩大攻击面 | 仅传入当前对话所需最小上下文 |

## 12. 结论

### 核心立场重申

1. **本产品不是诊断系统**。它是育儿记录与信息辅助工具，所有健康相关输出均为参考信息。
2. **不替代医生**。在任何存在不确定性的健康场景中，默认建议咨询儿科医生。
3. **高风险场景强制升级**。红旗症状、异常生长指标、疫苗不良反应等 P0/P1 场景，由 deterministic rules 强制触发就医/急救指引，LLM 无权覆盖。
4. **儿童数据最严格保护**。以 PIPL 为基线，最小收集、加密存储、显式授权、可随时删除。
5. **安全是发布前提**。任何版本发布必须通过安全门禁 checklist，安全 eval 不可跳过。

### 与前置任务的关系总结

| 前置任务 | 本文档如何衔接 |
|---|---|
| **A1（框架）** | 确认 deterministic rule engine 为安全判断的唯一执行者；safety_gate 架构细化 |
| **A2（架构）** | safety_gate 否决点的具体触发条件和行为定义；RBAC 权限模型详细设计 |
| **B1（知识库）** | L1/L2 层内容的变更审批流程；各层级的版权合规使用方式 |
| **B2（来源矩阵）** | 每类来源的具体使用边界和红线 |

### 对后续任务的约束

- **D1**：Schema 必须满足 §10.1 的 8 项约束（加密列、审计表、RBAC 表、过期字段等）。
- **E1**：Eval harness 必须包含 §10.2 的 7 类安全测试集。
- **G1**：Roadmap 必须满足 §10.3 的 5 项安全里程碑约束。

本文档应作为产品开发的安全基线，在后续所有设计和实现决策中具有约束力。任何偏离本文档要求的设计变更，需经安全 review + 产品负责人 + 医学顾问三方批准。
