## 1. 产品定位

为 0-6 个月新生儿家庭提供一个私有化、自部署的智能育儿 Agent。面向自家家庭成员使用，不是公共平台。

**核心能力：**
- 育儿知识指导（生长发育 + RAG 知识库，不做医疗诊断）
- 宝宝相册管理（AI 分类归档）
- 多角色对话（识别家庭成员身份）
- 综合记忆系统（短期 + 长期 + 全量存档）
- 数据收集与反馈（生长、喂养、睡眠、健康）

**交互形态：** Web 应用，Mobile-First 设计（主要在手机浏览器中使用）

**部署方式：** Docker Compose 容器化，先本地（NAS）部署，后续可迁移至云服务器

**非目标：**
- 不是公共平台或 SaaS 产品（仅自家使用）
- 不做原生移动应用（Mobile-First Web 设计）
- 不做多家庭/多租户支持（仅单个家庭）

---

## 2. 产品假设与使用边界

以下假设是整个架构和功能设计的前提，所有设计决策均基于此：

- **可信用户环境：** 所有使用者均为家庭成员，私有化部署在家庭网络内，不按公共 SaaS 安全合规模型设计
- **辅助型 Agent，非医疗系统：** Agent 是育儿辅助工具，不做医疗诊断、治疗方案或用药建议。安全边界通过 System Prompt 指引实现，不设独立的确定性安全模块
- **容忍模型少量误判：** 家庭自用产品，可接受 LLM 在非医疗场景下的少量错误。在不确定时，Agent 应主动说明不确定性而非拒绝回答
- **质量优先，不追求企业级体系：** 不需要复杂的 RBAC、审计日志、多租户隔离或 GDPR 合规。但工程质量不打折
- **局域网优先部署：** 默认部署在 NAS / 局域网，不假设公网暴露。如未来迁移至云服务器，再补充公网访问安全策略

---

## 3. 项目约束

- **团队规模：** 个人项目，AI 辅助编码，无其他开发者
- **时间线：** 无硬性 deadline，质量优先于速度
- **价值观：** 只接受"更优"的简化方案，不为省时间/资源而降低系统完整性
- **交付方式：** 不对用户分阶段发布，但内部按可验收里程碑集成，确保每一步都有可验证产物

## 6. 数据域

| 数据域 | 说明 |
|--------|------|
| 用户与权限 | 账号信息、家庭成员角色（Admin/Parent/Family）、JWT 认证 |
| 用户画像 | 每个家庭成员的结构化画像条目，由 Agent 自动维护，用户可查看/编辑/删除 |
| 宝宝档案 | 姓名、性别、出生日期、出生体重/身高/头围、是否早产、校正月龄 |
| 生长数据 | 身高、体重、头围、WHO 百分位（确定性计算） |
| 喂养数据 | 时间、方式（母乳/配方/辅食）、量 |
| 睡眠数据 | 入睡/醒来时间、夜醒次数 |
| 健康数据 | 疫苗接种、生病记录、就医记录 |
| 对话历史 | 全量消息永久保存，支持按日期/关键词检索 |
| 对话摘要 | 每次对话结束后 LLM 生成的摘要（长期记忆） |
| 知识库 | 权威育儿资料的向量化切片，支持 RAG 检索 |
| 照片 | MinIO 存储原图，PostgreSQL 存储 AI 标签和元数据 |

> 完整数据库 schema（DDL）见 [后端设计 Spec 第 3 章](BACKEND-DESIGN-V2.md)。

## 7. 功能模块

### 7.1 Advisor（育儿知识指导）

专注于 0-6 个月婴儿的生长发育和育儿知识指导，**不做医疗诊断和治疗建议**。

**信息源优先级：**
- **RAG 命中时：** 优先使用知识库权威内容，回答中标注来源（书名、章节）
- **RAG 未命中时：** Agent 可基于模型常识回答，但需在回复中说明"未检索到权威来源，以下为一般性建议"
- **医疗/异常相关问题：** 无论 RAG 是否命中，均更保守处理，优先建议咨询专业人士
- 所有健康相关回答附带"以医生意见为准"

**能做的：** 生长发育里程碑参考、喂养指导、睡眠指导、日常护理知识、生长数据解读。

**不做的：** 诊断、用药建议、治疗方案。遇到疾病/异常症状时，Agent 通过 System Prompt 中的安全指引自主判断并提醒就医（不设独立的确定性安全模块）。

### 7.2 Album（相册系统）

- 上传照片 → Vision API 自动分析（场景识别、表情/状态识别、候选里程碑检测）
- AI 标签保存置信度，里程碑标签需用户确认（单张照片不能可靠判断"第一次"）
- 三种浏览模式：按时间线 / 按场景分类 / 按里程碑

### 7.3 Memory（记忆系统）

三层架构：

| 层级 | 用途 |
|------|------|
| 短期记忆 | 当前会话上下文，维持对话连贯性 |
| 长期记忆 | 历史对话摘要，新对话时自动加载，Agent "记得"之前聊过什么 |
| 全量存档 | 所有历史对话完整原文，永久保存，面向用户的检索功能 |

**会话边界：** 用户主动新建对话，或 30 分钟无活动自动结束。结束后触发摘要生成和用户画像更新。

### 7.4 Tracker（数据收集与反馈）

四个数据域，通过对话式自然语言输入：

| 数据域 | 记录内容 | 反馈能力 |
|--------|---------|---------|
| 生长 | 身高、体重、头围 | WHO 百分位对比（确定性计算）、生长趋势曲线 |
| 喂养 | 时间、方式、量 | 日累计量、喂养间隔分析 |
| 睡眠 | 入睡/醒来、夜醒次数 | 日均睡眠时长、与月龄参考对比 |
| 健康 | 疫苗、生病、就医 | 疫苗日程提醒、健康时间线 |

**写入确认规则：**
- **高置信写入：** 关键字段完整且语义明确时（如"宝宝今天体重 4.2kg"），Agent 直接写入并在回复中告知"已记录体重 4.2kg"
- **追问补全：** 缺少关键字段、时间不明确、单位不明确或语义有歧义时，Agent 先追问确认再写入
- **防重复：** 同一数据域、同一时间段已有记录时，Agent 应提示已有记录并确认是否覆盖
- **纠错更新：** 用户纠正时（如"不是 4.2，是 4.6"），Agent 更新最近一条相关记录而非新增
- **前端可编辑：** 用户可在数据看板页面直接编辑或删除已记录的数据

### 7.5 Auth（用户与角色管理）

| 角色 | 权限 |
|------|------|
| Admin | 系统配置、管理家庭成员、全部功能 |
| Parent（父母） | 全部功能：对话、记录、查看、上传照片 |
| Family（其他成员） | 可对话、可查看数据；上传照片和写入 Tracker 由 Admin 配置决定 |

家庭成员通过配置预设（不做自助注册），Agent 通过 JWT 中的角色信息自动识别"谁在问"，调整回答语气和侧重点。

画像内容仅本人和 Admin 可见，不对其他角色展示。

### 7.6 用户画像系统

- 每个家庭成员维护一份画像，由 Agent 根据对话内容自动维护
- 逐条管理（非整体覆盖），每条记录来源对话 ID，支持追溯
- 仅记录与育儿相关的事实性信息，避免主观推断
- 用户可在"我的"页面查看、编辑、删除画像条目

### 7.7 RAG 知识库

**来源准入：**

| 允许入库 | 不允许入库 |
|---------|-----------|
| WHO/CDC/卫健委等官方指南 | 个人博客、论坛帖子 |
| 权威育儿书籍（专业作者出版物） | UGC 内容 |
| 医学期刊公开摘要 | 商业推广内容 |

每份入库资料需记录：来源名称、作者/机构、出版/发布日期。增量式建设，随时可添加新内容。

## 8. 前端页面

**设计原则：** Mobile-First，主要在手机浏览器中使用。底部 Tab 导航（对话 / 数据 / 相册 / 我的）。

**对话页（核心）：** 类微信聊天界面，支持文字和图片。Agent 回复中可嵌入数据卡片。顶部入口进入历史对话检索。

**数据看板页：** 宝宝基本信息、生长曲线（含 WHO 参考线）、喂养统计、睡眠统计、健康时间线。

**相册页：** 三种浏览模式切换（时间线/场景/里程碑）、照片预览、AI 标签查看与确认、上传入口。

**我的页面：** 个人信息、宝宝档案编辑、画像查看/编辑、Admin 家庭成员管理。

> 视觉设计系统（配色、字体、组件样式）见 [DESIGN.md](DESIGN.md)。
> 实现细节（类型、状态管理、API 契约、组件接口）见 [前端设计 Spec](FRONTEND-DESIGN-V2.md)。

## 9. 部署

Docker Compose 一键部署：`docker compose up` 启动全部服务（前端、后端、PostgreSQL、MinIO），首次启动自动完成数据库初始化。

先部署在本地 NAS，后续可无缝迁移至云服务器。

> 部署配置详情见 [后端设计 Spec 第 13 章](BACKEND-DESIGN-V2.md)。

## 10. 验收标准

### 功能验收

- [ ] **自然语言记录 + 智能反馈：** 妈妈发送"宝宝今天体重 4.2kg，是不是偏轻了？"，Agent 完成：①写入体重到 Tracker 并告知已记录 ②通过 WHO LMS 确定性计算百分位 ③结合 RAG 知识库解释并给出建议
- [ ] **Tracker 写入纠错：** 用户发送"不对，是 4.6kg"，Agent 更新上一条体重记录为 4.6kg 而非新增
- [ ] **Tracker 追问补全：** 用户发送"宝宝吃了奶"（缺少量和方式），Agent 追问补全后再写入
- [ ] **多角色数据共享：** 妈妈记录喂养数据后，奶奶登录询问"宝宝今天吃了多少"，Agent 能基于奶奶的角色和妈妈记录的数据回答
- [ ] **照片上传 + AI 分类：** 上传后 Vision API 自动打标签（含置信度），里程碑需用户确认，三种模式浏览
- [ ] **数据可视化看板：** 生长曲线（含 WHO 参考线）、喂养统计、睡眠统计
- [ ] **前端数据编辑/删除：** 用户可在数据看板页面直接编辑或删除错误的 Tracker 记录
- [ ] **历史对话检索：** 所有对话永久保存，按日期浏览 + 关键词搜索
- [ ] **记忆系统：** 对话结束后自动生成摘要，新对话加载历史上下文
- [ ] **用户画像：** Agent 自动维护，用户可查看/编辑/删除

### 知识与安全验收

- [ ] **RAG 来源标注：** RAG 命中时回答附带来源信息；未命中时明确说明"未检索到权威来源"
- [ ] **安全提醒：** 用户描述异常症状（如"宝宝发烧 39 度"），Agent 提醒就医并附带"以医生意见为准"，不做诊断
- [ ] **不确定性说明：** RAG 未命中的非医疗问题，Agent 基于常识回答但说明不确定性

### 工程验收

- [ ] **LLM 可切换：** 修改配置即可切换 Claude ↔ GPT
- [ ] **一键部署：** `docker compose up` 启动全部服务，首次自动完成初始化

### 体验目标

- [ ] **家人体验验证：** 家庭成员实际使用一周后评价"比直接用 ChatGPT 好用"
