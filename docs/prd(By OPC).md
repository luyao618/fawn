## 1. 产品概述

### 1.1 产品愿景

为 0–6 岁婴幼儿家庭提供一个**智能记录与辅助决策 Agent**，让新手父母在喂养、睡眠、生长、疫苗、症状应对等方面获得结构化记录、及时提醒和有据可查的育儿参考信息。

### 1.2 一句话定位

> Fawn 是一个**育儿记录与信息辅助工具**，**不是**医疗诊断系统，**不**替代任何医疗专业人员。

### 1.3 核心价值主张

| 价值 | 说明 |
|------|------|
| **记录省心** | 自然语言输入即可完成喂养/睡眠/生长/疫苗记录，无需手动填表 |
| **提醒及时** | 疫苗到期、生长测量、喂养间隔等关键时间节点自动提醒 |
| **安全兜底** | 高风险症状自动识别并建议就医，决不做"安抚式"回答 |
| **家庭协作** | 父母/祖辈/保姆多角色协作，共享宝宝记录 |
| **隐私保守** | 儿童数据最小收集、加密存储、可随时删除 |

## 2. 产品定位与边界

### 2.1 能做

| 功能 | 执行方式 | 来源 |
|------|---------|------|
| 记录喂养量/次数/时间（母乳/配方/辅食） | 数据结构化写入，趋势可视化 | D1 |
| 记录睡眠时长/模式 | 数据写入，与月龄参考范围对比 | D1 |
| 记录身高/体重/头围，绘制 WHO 生长曲线 | Deterministic：WHO Z-score 计算 | C1 |
| 疫苗日程提醒（中国免疫规划） | Deterministic：规则引擎排程 | C2 |
| 一般育儿知识问答 | LLM + RAG，标注来源 | B1/B2 |
| 发育里程碑对照提示 | Deterministic：CDC 里程碑 checklist | C1 |
| 症状描述 → 分诊建议 | 双通道解析 + 规则引擎 + safety_gate | C2/F1 |

### 2.2 不能做

| 禁止行为 | 执行方式 | 来源 |
|---------|---------|------|
| 出具诊断结论 | 硬编码拒绝 | F1 |
| 推荐处方药 / 修改医嘱 | 硬编码拒绝 | F1 |
| 替代急救指导的"个性化调整" | 仅展示标准急救流程原文 | F1 |
| 计算药物剂量/推荐用药 | 不做剂量计算 | F1 |
| LLM 自主判断症状严重程度 | 由 Rule Engine 判断 | A2/F1 |
| LLM 自主调整 RBAC 权限 | 权限变更必须人工确认 | F1 |
| LLM 自主决定删除用户数据 | 删除操作必须人工确认 | F1 |

### 2.3 必须升级

以下场景触发强制升级，由规则引擎直接执行，**不经过 LLM 判断**：

- 红旗症状触发（高热惊厥、呼吸困难、嗜睡拒食等）→ 中断对话 → 展示急救/就医指引
- 生长 Z-score < -3 或 > +3 → 强提示就医
- 疫苗严重不良反应描述 → 就医指引
- 误服异物 / 中毒 / 跌落后意识改变 → 拨打 120

## 3. 目标用户画像

### 3.1 主要用户

| 角色 | 特征 | 核心需求 |
|------|------|---------|
| **新手妈妈（25-35 岁）** | 首次育儿，信息焦虑，频繁查询育儿知识 | 快速记录、生长监测、知识问答、症状判断 |
| **新手爸爸（25-35 岁）** | 参与育儿但经验不足，想了解宝宝日常 | 查看记录、协作记录、接收提醒 |
| **祖辈照护者（50-65 岁）** | 日常照护执行者，与年轻父母存在育儿观念差异 | 简单操作记录喂养/睡眠，查看宝宝信息 |
| **保姆/月嫂** | 职业照护者，需交接记录 | 只读查看、基础记录 |

### 3.2 家庭结构

```
Family Unit (家庭)
├── Primary Guardian (主监护人) — 全部权限
├── Co-Guardian (共同监护人) — 大部分权限
└── Viewer (只读) — 祖父母/保姆，仅查看结构化记录摘要
```

### 3.3 用户场景举例

| 场景 | 用户 | 输入 | 期望输出 |
|------|------|------|---------|
| 快速记录 | 妈妈 | "宝宝刚喝了120ml奶粉" | "已记录：配方奶120ml ✓ 今日累计480ml" |
| 生长监测 | 爸爸 | "宝宝6个月，7.2kg，66cm" | WHO 百分位对比 + 正常/异常提示 |
| 症状咨询 | 妈妈 | "宝宝3个月，体温39.5，精神很差" | 立即显示就医指引（规则引擎触发，不经 LLM） |
| 疫苗提醒 | 系统 | 宝宝即将满2月龄 | 推送"建议接种：脊灰灭活疫苗(IPV)第1剂" |
| 协作查看 | 奶奶 | "今天谁给宝宝喂过奶" | 展示今日喂养记录摘要 |

### 3.4 MVP 成功指标

| 指标 | 目标 | 说明 |
|------|------|------|
| 内测家庭数 | ≤ 100 | Phase 1 发布后首批用户 |
| 周活跃率（WAU） | ≥ 60% | 至少每周使用一次记录功能 |
| 记录完成率 | ≥ 80% | 开始输入 → 成功保存的转化率 |
| safety_gate 假阳性率 | ≤ 5% | 过度拦截不应影响正常使用 |
| P0 医疗场景误判率 | 0% | 红旗症状、急救场景零漏判 |
| 30 天留存率 | ≥ 40% | 首次使用后 30 天仍活跃 |

## 4. 核心功能需求

### 4.1 喂养记录

**优先级**：P0（MVP）

| 需求项 | 说明 | 实现方式 |
|--------|------|---------|
| 支持母乳/配方奶/辅食/水记录 | 喂养方式 ENUM：breast, formula, mixed, solid, water | LLM 解析 → 结构化写入 |
| 记录量/时间/时长 | amount(ml/g), duration_min, side(left/right/both) | LLM 提取 + 规则校验 |
| 日累计量提示 | 超过年龄建议上限时温和提醒 | Rule Engine 判断 |
| 常见异常标记 | 吐奶、拒食、过敏等 reaction_flags | LLM 提取 + 规则触发 |
| 输入验证 | amount ∈ [10, 500]ml 等合理范围检查 | Rule Engine |

**数据模型**：`feeding_event` 子表（D1），关联 `timeline_event`。

### 4.2 睡眠记录

**优先级**：P0（MVP）

| 需求项 | 说明 | 实现方式 |
|--------|------|---------|
| 入睡/醒来时间 | sleep_start_at, sleep_end_at | LLM 解析 |
| 睡眠类型 | night/nap/contact_nap/unknown | LLM 分类 |
| 夜醒次数 | wake_count | LLM 提取 |
| 哄睡方式 | settling_method（自由文本） | LLM 提取 |
| 睡眠质量评分 | quality_score（可选） | 用户输入 |
| 与月龄参考范围对比 | 连续3天异常 → 提示 | Rule Engine（Phase 2） |

**数据模型**：`sleep_event` 子表（D1），关联 `timeline_event`。

### 4.3 生长曲线

**优先级**：P0（MVP）

| 需求项 | 说明 | 实现方式 |
|--------|------|---------|
| 支持身高/体重/头围三指标 | 精度：体重 NUMERIC(5,2)（精度到10g），身高头围 NUMERIC(5,2)（精度到0.1cm） | 结构化输入 |
| WHO Z-score 计算 | LMS 方法，极端值修正（\|z\|>3） | Deterministic Rule Engine |
| 百分位展示 | Φ(z)×100，保留1位小数 | Deterministic |
| 体位修正 | <2岁站量+0.7cm，≥2岁躺量-0.7cm | Deterministic |
| 早产儿校正月龄 | <37周，校正至24月龄（体重/身高）/ 18月龄（头围） | Deterministic |
| 四级告警 | NORMAL / WATCH / REVIEW / URGENT | Rule Engine 阈值判定 |
| 趋势穿越检测 | 百分位线穿越1条→WATCH，2条→REVIEW | Rule Engine |
| 家长友好展示 | 不显示 z-score 原始值（避免焦虑），只显示百分位 | UI 约束 |

**标准选择路由**：
- 默认：WHO 2006（0-5岁），WHO 2007 Reference（5-18岁）
- 可选：中国 WS/T 423（待数字化）、CDC 2000
- 早产儿：Fenton 2013

**数据模型**：`growth_event` 子表（D1），包含所有计算字段。

### 4.4 疫苗提醒

**优先级**：P0（MVP）

| 需求项 | 说明 | 实现方式 |
|--------|------|---------|
| 中国 NIP 一类疫苗覆盖 | 12种疫苗，含 HepB/BCG/IPV/DTaP/MMR/JE-L 等 | 规则配置文件 |
| 剂次状态管理 | SCHEDULED→REMINDED→GIVEN/OVERDUE/DEFERRED | 状态机（C2） |
| 提前提醒 | 接种日前 7/3/1 天 | Temporal Workflow（Phase 2前用简单定时） |
| 逾期提醒 | 逾期后 1/7/14/30 天 | Temporal Workflow |
| 接种确认 | 家长确认已接种，记录时间/机构/批号 | 用户操作 |
| 接种后不良反应随访 | +30min / +4h / +24h / +72h 主动询问 | follow_up_task |
| 禁忌症筛查（Phase 2） | 接种前问卷（发热？过敏？免疫抑制？） | Rule Engine |
| 补种计算（Phase 2） | 逾期自动生成补种方案 | Rule Engine |
| 地区路由 | schedule_region: CN / US / WHO_DEFAULT | 配置化 |

**数据模型**：`vaccine_event` 子表（D1），含 status/dose_no/schedule_region 等。

> **⚠️ 待人工复核**：疫苗时间表、补种规则、禁忌清单的具体数值需医学顾问按最新版《国家免疫规划疫苗儿童免疫程序说明》逐条审定。

### 4.5 症状分诊

**优先级**：P0（MVP — 仅 L3 急诊规则；Phase 2 补全三级分诊）

#### 三级分诊模型

| 级别 | 标签 | 含义 | 产品行为 |
|------|------|------|---------|
| L3 | `EMERGENCY_120` | 急诊/拨打 120 | 立即显示急救提示 + 引导拨打 120 |
| L2 | `SEE_DOCTOR` | 尽快就医 | 建议 24h 内就诊 |
| L1 | `HOME_CARE` | 居家观察 | 提供护理指导 + 随访提醒 |

**核心原则**：不确定时一律升级。L1 可以误判为 L2，但 L3 绝不可降级。

#### L3 急诊规则（MVP 必须覆盖，示例）

| Rule ID | 条件 | 响应 |
|---------|------|------|
| E001 | <3月龄 AND 体温≥38°C | 立即就医 |
| E002 | 呼吸困难（胸骨凹陷/鼻翼煽动） | 拨打120 |
| E003 | 抽搐/惊厥 | 保持侧卧 + 拨打120 |
| E004 | 发绀（嘴唇/面部发紫） | 拨打120 |
| E005 | 严重过敏反应（面部肿胀+呼吸困难） | 拨打120 |
| E006 | 意识改变/嗜睡难以唤醒 | 拨打120 |
| E008 | 误服异物/中毒/严重烧烫伤 | 拨打120 |

#### 双通道安全解析流程

```
用户描述症状
    ↓
[raw-text prefilter] — 关键词/regex/数值阈值/注入特征扫描（不依赖 LLM）
    ↓
[LLM semantic parser] — 自然语言归一化 → 结构化 symptom_event
    ↓
[merge] — 两路结果取风险更高者；冲突默认升级
    ↓
[Rule Engine] — 匹配规则，按优先级 E* > D* > H*
    ↓
[safety_gate] — 最终否决权：月龄<3兜底、多规则取最高、低置信升级
    ↓
[输出] — 分诊结果 + LLM 生成话术 + 免责声明 + 随访任务
```

**数据模型**：`symptom_event` 子表（D1），含 `symptom_code`/`severity`/`rule_evaluation`（JSONB）等；分诊结果存储在 `timeline_event.risk_level` + `timeline_event.rule_ids_triggered`。

## 5. 技术架构决策

### 5.1 架构总览

```
Client (微信小程序/Flutter/Web)
    ↓ HTTPS/WebSocket
API Gateway (认证/限流/RBAC/审计)
    ↓
┌──────────────┬──────────────┬──────────────┬────────────────┐
│  主 Agent    │  Temporal    │  Rule        │  Plugin/Tool   │
│  (LangGraph) │  Workflows   │  Engine      │  Layer         │
│              │              │              │                │
│  意图识别    │  疫苗提醒    │  红旗分诊    │  生长曲线计算  │
│  对话管理    │  定期随访    │  Z-score计算  │  喂养/睡眠记录 │
│  工具路由    │  重试补偿    │  阈值判定    │  通知发送      │
│  回复生成    │  数据保留    │  安全否决    │  家庭管理      │
└──────┬───────┴──────┬───────┴──────┬───────┴────────┬───────┘
       └──────────────┴──────────────┴────────────────┘
                              ↓
                  Data Layer (PostgreSQL + Redis + MinIO)
```

### 5.2 关键技术选型

| 组件 | 选型 | 理由 | 来源 |
|------|------|------|------|
| Agent 编排 | LangGraph | 图状态机，支持 deterministic + LLM 混合编排 | A1 |
| 持久工作流 | Temporal | 疫苗提醒/随访等跨天任务需要 durable execution | A1 |
| 规则引擎 | 自建 (Python/JSON-DSL) | 医疗规则100%确定性执行，不依赖 LLM | A1/A2 |
| 主数据库 | PostgreSQL | 唯一事实主库，支持列级加密、事务、审计 | D1 |
| 缓存 | Redis | 会话热状态、幂等窗口、速率限制 | D1 |
| 对象存储 | MinIO | 图片/音频/视频/扫描件 | D1/D2 |
| 向量索引 | pgvector | MVP 先用 pgvector，规模增大再外扩 | D1 |
| LLM | Claude Sonnet / GPT-4o-mini | 成本/质量平衡；意图分类可用更小模型 | A2 |

### 5.3 Deterministic Rules vs LLM 分工

| 功能 | Rule Engine | LLM | 最终决定权 |
|------|------------|-----|-----------|
| 红旗症状识别 | ✅ 关键词 + 阈值 | 辅助意图理解 | **Rule Engine** |
| 生长曲线计算（Z-score/百分位）| Plugin/Tool 层计算 | ❌ | **Rule Engine**（阈值判定）|
| 生长曲线评估（告警分级）| ✅ NORMAL/WATCH/REVIEW/URGENT | 生成解释文案 | **Rule Engine** |
| 疫苗排程 | ✅ 日程计算 | 生成提醒文案 | **Rule Engine** |
| 喂养/睡眠记录 | ✅ 数据校验 | 自然语言解析 | **Rule Engine**（校验）|
| 年龄合规校验 | ✅ 功能可用性 | ❌ | **Rule Engine** |
| 剂量安全范围校验 | ✅ 仅校验上报值是否合理 | ❌ | **Rule Engine**（不做推荐）|
| 一般育儿问答 | safety_gate 输出过滤 | ✅ RAG + 生成 | **safety_gate** |
| 免责声明 | ✅ 自动附加 | ❌ 不参与 | **Rule Engine** |
| RBAC | ✅ 权限校验 | ❌ 不参与 | **RBAC 引擎** |
| 诊断/处方/用药 | ❌ 都不做 | ❌ 都不做 | **产品边界** |

**核心原则**：LLM 做"翻译"，Rule Engine 做"判断"，safety_gate 做"否决"。三层串联，不可跳过。

### 5.4 LangGraph ↔ Temporal 集成

- LangGraph 负责**同步交互编排**（单次请求内可完成的对话、路由、工具调用）
- Temporal 负责**跨时间边界的 durable execution**（定时提醒、重试、随访、跨天任务）
- **强制约束**：超过当前请求生命周期的动作一律进入 Temporal
- **幂等保护**：`workflow_business_id = <family_id>:<baby_id>:<workflow_type>:<trigger_scope>`
- **启动约束**：LangGraph 只能通过统一 `WorkflowApplicationService` 发起 Temporal workflow，禁止在 graph node 中直接调用 `client.start_workflow()`；启动需经 outbox/bridge 模式保证事务一致性；定时 reconciliation job 检测孤立 workflow（详见 A2 §4.3）

### 5.5 safety_gate 机制

所有 Agent 输出在送达用户前，必须经过 safety_gate 最终审核：

| 检查项 | 规则 | 失败行为 |
|--------|------|---------|
| LLM 不得降级告警 | 不能将 REVIEW/URGENT 表述为"正常" | 替换为安全模板 |
| LLM 不得编造数值 | 百分位/z-score 必须与规则引擎一致 | 替换为安全模板 |
| LLM 不得给出诊断 | 不含疾病名称作为结论 | 删除诊断语句 |
| LLM 不得建议用药 | 不含用药/治疗方案 | 替换为"请咨询医生" |
| 免责声明必须存在 | 健康相关回答必带免责声明 | 强制附加 |
| 月龄 < 3 兜底 | <3月龄任何异常一律升级至 EMERGENCY | 强制升级 |
| 多源冲突取最高 | prefilter 与 parser 冲突时取更高风险 | 不允许降级 |
| 低置信度升级 | NLU 置信度 < 0.7 时升级至 SEE_DOCTOR | 强制升级 |
| 注入检测保守 | 检测到指令型文本("忽略症状"等)时进入保守模式 | 保守升级 |

## 6. 知识体系

### 6.1 六层知识架构

```
L1: 硬编码医学规则  ←── Deterministic, 否决权, ~500条
L2: 结构化医学知识  ←── Deterministic + 查表, ~10K条
L3: 育儿百科文档    ←── RAG 检索, 参考级, ~50K chunks
L4: 经验知识        ←── RAG 检索, 辅助级, ~100K chunks
L5: 家庭档案        ←── 个性化存储, 按家庭增长
L6: 对话记忆        ←── 短期+长期记忆, 按会话增长
```

### 6.2 检索策略

**"规则优先、向量兜底"的级联策略**：
1. 意图分类 → 确定需要查询的知识层级
2. L1/L2 有确定性答案 → 直接返回规则结果
3. L1/L2 无匹配 → L3/L4 向量检索 + RAG 生成
4. 所有结果经 safety_gate 最终审核

### 6.3 来源分级

| 来源层级 | 使用方式 | 版权策略 |
|---------|---------|---------|
| WHO/CDC/卫健委规范 | 数值硬编码入规则引擎 | 公共数据，标注来源 |
| WHO 立场文件/NHS/NICE | 摘要引用 + 来源链接 | 不全文入库，引用标注 |
| AAP/UNICEF | 仅存储 metadata | 不入库正文，引导访问原站 |
| UGC | 不入库、不引用 | 无法验证准确性 |

## 7. 数据模型

### 7.1 核心实体关系

```
Family 1—N Member
Family 1—N BabyProfile
BabyProfile 1—N TimelineEvent
TimelineEvent 1—0..1 FeedingEvent / GrowthEvent / SleepEvent / VaccineEvent / SymptomEvent
TimelineEvent 1—N MediaAsset
WorkflowRun 1—N Reminder / FollowUpTask
```

### 7.2 统一时间线 + 高价值子表

- `timeline_event`：统一事件入口，保证回放与审计
- 高价值子表（`feeding_event`, `growth_event`, `sleep_event`, `vaccine_event`, `symptom_event`）：强结构化，支撑规则引擎直接读取
- `payload_snapshot`（JSONB）：存最小必要摘要，不替代强结构化子表

### 7.3 工作流落表

| 表 | 职责 |
|----|------|
| `workflow_run` | Temporal 工作流执行记录，含状态/输入输出快照 |
| `scheduled_job` | 调度配置（cron/定时） |
| `reminder` | 提醒记录（疫苗/生长/随访） |
| `follow_up_task` | 随访任务（症状/接种后/生长复测） |
| `idempotency_key` | 幂等保护，防重复操作 |

### 7.4 会话、授权与生命周期

| 表 | 职责 |
|----|------|
| `conversation_session` | 会话跟踪，含 `summary_text`（Viewer 脱敏读取字段）、风险级别 |
| `consent` | 用户同意条款版本化存储，PIPL 合规必需 |
| `media_asset` | 多模态媒体资产（Phase 3），含 PII 级别/人脸标记 |
| `annotation` | 媒体标注/候选结果，含置信度/复核状态 |
| `retention_deletion_policy` | 数据保留与删除策略，驱动数据生命周期 |
| `audit_log` | 全操作审计，append-only |

### 7.5 检索与知识治理

| 表 | 职责 |
|----|------|
| `source_registry` | 来源注册，含许可/地区/版本/层级 |
| `document_chunk` | 知识库切片 |
| `embedding` | 向量索引 |
| `citation` | 引用追溯 |

## 8. 安全、隐私与合规

### 8.1 风险分级

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 — 生命安全 | 可能延误急救 | 立即急救指引 + 强制建议拨打120 |
| P1 — 健康偏差 | 可能错过窗口期 | 标记异常 + 建议预约儿科 |
| P2 — 信息误导 | 可能传播不准确信息 | 标注来源等级 + 提示咨询医生 |
| P3 — 体验瑕疵 | 不影响安全但影响信任 | 常规 bug-fix |

### 8.2 适用法规

| 法规 | 要求 |
|------|------|
| 中国 PIPL | 不满14周岁属"敏感个人信息"，需父母单独同意 |
| 中国《未成年人保护法》| 不得收集非必要未成年人信息 |
| COPPA（若服务美国）| 13岁以下需 verifiable parental consent |
| GDPR Art.8（若服务欧盟）| 16岁以下需父母同意 |

**推荐**：以 PIPL 为默认基线（最严格之一）。

### 8.3 加密方案

| 层级 | 方案 |
|------|------|
| 传输加密 | TLS 1.3，HSTS 强制 |
| 静态加密 — 数据库 | AES-256-GCM 列级加密（高敏感字段） |
| 密钥管理 | Envelope Encryption：KEK 仅存 KMS/HSM，数据库只存 DEK 密文 |
| 密钥轮换 | ≤ 90 天；支持后台逐步 rewrap |

**查询约束**：需要精确查询的高敏字段使用 blind index / tokenization，不允许保留明文副本用于索引。

**必须列级加密的字段**：
- `baby_profile`: name, dob, birth_weight/height/head_circ
- `growth_event`: weight_kg, height_cm, head_circ_cm
- `vaccine_event`: vaccine_name, provider_name, batch_no
- `symptom_event`: symptom_text
- `member`: phone_or_email

### 8.4 数据保留与删除

| 数据类型 | 保留期 | 删除方式 |
|---------|--------|---------|
| 结构化健康记录 | 直到用户主动删除 | 硬删除 + 备份清理 |
| 对话历史 | 90天 | 自动摘要化（提取至 `conversation_session.summary_text`）后删除原文 |
| 审计日志 | 3年 | 到期自动清理（不可用户删除） |
| 账户注销 | 30天冷静期后永久删除 | 硬删除 + 备份90天内清理 |

### 8.5 免责声明

| 场景 | 模板 | 可跳过？ |
|------|------|---------|
| 一般育儿问答 | "以上信息仅供参考，不构成医疗诊断或治疗建议" + 来源标注 | ❌ |
| 红旗症状触发 | "请立即就医" + 急救指引（固定文案，不经 LLM） | ❌ |
| 首次使用 | 数据与隐私告知 | ❌ |

## 9. 评测与质量门禁

### 9.1 评测维度

| 维度 | 评测方式 | 目标 |
|------|---------|------|
| 对话理解与输出 | Golden set + LLM-as-judge（仅非安全场景）| 意图准确率 ≥ 95% |
| Tool-call 正确性 | Deterministic 断言 | 准确率 ≥ 98% |
| DB 状态正确性 | JSON diff + 规则断言 | 100% 正确 |
| Workflow 正确性 | Temporal trace 对齐 | 100% 正确 |
| 安全/隐私边界 | 规则断言（禁止 LLM-as-judge）| P0 医疗场景 0 误判 |
| 回归与回放 | 全链路可重放 | 每次发版必须通过 |

### 9.2 发布门禁 Checklist

```
[ ] safety_gate 单元测试全部通过（覆盖所有红旗症状场景）
[ ] 免责声明插入测试通过
[ ] RBAC 权限测试通过（越权测试 0 通过）
[ ] 加密字段验证（敏感字段确认加密存储）
[ ] LLM 输出安全 eval 通过（adversarial 测试集）
[ ] 数据删除流程验证
[ ] 审计日志完整性验证
[ ] 版权合规审查
[ ] 隐私政策与实际行为一致性检查
[ ] 医学内容变更专业人员 sign-off
```

### 9.3 评测红线

- **禁止 LLM-as-judge 的场景**：安全边界判断、医学结论、权限边界、隐私泄漏
- **Golden set 产出方式**：联合医学专家预裁决，禁止 LLM 参与金集输出制定
